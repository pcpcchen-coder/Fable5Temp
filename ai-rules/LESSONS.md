# LESSONS · 踩坑記錄（append-only）

> 用法：踩坑後**當下**追加一條到本檔最上方（新的在上），格式照下面的模板。
> 只追加、不改寫舊條目。超過 30 條或 250 行 → 觸發精簡（流程見 `40-maintenance.md` 第 4 節）。
> 「踩坑」的定義：任何讓你浪費超過 3 輪對話、或產出被驗證打回、或事後發現方向錯了的事。
> 另收「提案」類條目（標籤：提案）：需要使用者裁決的制度變更建議（見 `40-maintenance.md` 第 1 節）。

## 條目模板（複製這段來用）

```
## YYYY-MM-DD | 標籤（如：派工/驗證/git/環境/搜尋） | 一句話教訓
- 情境：當時在做什麼
- 錯誤：實際做錯了什麼（含關鍵指令或判斷）
- 正確做法：下次該怎麼做
- 規則化：無｜已寫入 <檔名> 第 N 節（精簡時填）
```

## 2026-07-04 | 派工/環境 | 大量平行 subagent 會撞 session 用量上限；大型 fan-out 前先想額度
- 情境：多代理複審 workflow 一次排入 60 個對抗驗證 agent
- 錯誤：未預估 session 用量額度，第 22 個驗證起全數失敗（額度於 4am UTC 重置），報告階段一併中斷
- 正確做法：此類失敗屬環境暫時性、不計入錯誤次數；等額度重置後用 workflow resume 從快取續跑（本次實測：31 個已完成 agent 全數快取命中、零重工）。排大型平行驗證時分批，或在額度將盡時改序列
- 規則化：無
