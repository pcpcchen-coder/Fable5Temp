# 30 · 派工 prompt 模板（直接複製填空）

> 最後更新：2026-07-04｜原因：初版
> 用法：選對應任務型態的模板 → 複製 → 填掉所有 `〔〕` → 檢查沒有留空的〔〕→ 派工。
> `〔〕` 全形括號是填空記號，派出去的 prompt 裡**不准殘留**。
> 模型與 agent 的選法見 `10-model-dispatch.md` 第 2、8 節；模板已附建議值。

## 共用底座（所有模板的結尾都要有這段）

```
【回報格式】只准以下欄位，總長 ≤30 行：
- 結論（≤10 行，直接回答目標）
- 關鍵位置（檔案路徑:行號；每個論斷都要有出處）
- 未解事項與信心（沒查到的、不確定的，明說；禁止用猜測填補）
- 長產物：寫到〔指定路徑〕，回報只給路徑
禁止：貼整檔內容回來；宣稱完成但不附證據；用猜測填補查不到的空白。
找不到／做不到就照實回報「做不到＋已試過什麼」，這是合格回報。
```

## 模板 1：搜尋／定位（建議：scout 或 Explore；model=haiku，難的用 sonnet）

```
【目標】找出〔要找的東西：定義／呼叫點／設定值／某檔案是否存在〕。
【動機】我接下來要〔用這個位置做什麼〕，所以需要精確位置而不是大概方向。
【範圍】搜尋範圍限定在〔目錄／檔案類型〕；不需要讀懂邏輯，只要定位。
【驗收條件】
1. 每個找到的結果附 檔案路徑:行號
2. 找不到時，列出試過的所有搜尋 pattern（至少 3 種變體）再下結論
＋共用底座
```

## 模板 2：實作（建議：implementer；model=sonnet, effort=medium）

```
【目標】〔做出什麼，一句話〕。
【動機】〔為什麼做、產出會被怎麼用〕。上游脈絡：〔一句，例如「這是 X 任務的第 2 步」〕。
【範圍】只准動這些檔案：〔清單〕。明確不要動：〔清單或「其他一律不動」〕。
【做法提示】〔可省略；已知的坑、該沿用的既有模式〕
【驗收條件】（可機械判定，逐條列）
1. 〔例：新檔 X 存在且包含 A、B、C 三節〕
2. 〔例：測試指令 Y 全綠，貼最後 10 行輸出〕
3. diff 只含上述範圍內的變更
【自檢】交付前自己先對照驗收條件過一遍；但你的自檢不是驗收，驗收由另一個 agent 做。
＋共用底座
```

## 模板 3：重構（建議：implementer；model=sonnet, effort=high）

```
【目標】把〔對象〕從〔現狀〕重構為〔目標形態〕，外部行為不變。
【動機】〔為什麼值得動它〕。
【範圍】只准動：〔清單〕。公開介面／對外行為一律不變，發現不得不變時停下回報，不要自行決定。
【分批】超過 5 個檔時分批做，每批可獨立 revert；先完成 1 個檔作為試點，試點通過驗收才繼續。
【驗收條件】
1. 行為不變的證據：〔測試指令〕重構前後皆全綠（先跑一次記錄基準，改完再跑一次）
2. 〔結構性驗收，例：重複的 X 邏輯只剩一份，位於某檔〕
3. diff 不含任何行為變更（重命名與搬移除外）
＋共用底座
```

## 模板 4：研究／查證（建議：general-purpose；model=sonnet，關鍵決策研究用 opus。
查 Claude Code／Claude API 事實改用 claude-code-guide）

```
【目標】回答：〔具體問題，一句話問完〕。
【動機】答案將用來〔決定什麼〕，所以錯誤答案的代價是〔什麼〕。
【範圍】優先查〔官方文件／指定來源〕；訓練記憶只能當線索，不能當結論。
【驗收條件】
1. 每個關鍵論斷附來源（URL 或 檔案路徑:行號）
2. 「已查證」與「推測」分開標示；查不到的寫「查不到」，禁止編造
3. 完整研究內容寫到〔指定路徑〕，回報只給結論摘要與路徑
＋共用底座
```

## 模板 5：審查／驗收（建議：verifier；model=sonnet, effort=high。
高風險改動升 opus 或加派第二位不同角度的審查者）

```
【目標】驗收以下產出：〔產出的位置：檔案路徑／commit／分支〕。
【你是誰】fresh-context 驗收者。你沒有、也不需要實作過程的資訊；
只依驗收條件與你自己讀到／跑到的證據下判斷。實作者的說法不算證據。
【姿態】先試著推翻它：假設產出有錯，找證據證明；找不到錯才給 PASS。
【驗收條件】（逐條核對）
1. 〔條件一，原樣複製自當初的派工單〕
2. 〔條件二〕
【驗法】檔案類：實際 Read 全文對照。程式碼類：跑〔測試／指令〕，貼關鍵輸出；
跑不了要寫明原因並標註「未經執行驗證」。
【回報格式】逐條「PASS／FAIL＋證據（file:line 或指令輸出）」；
最後一行給總判定：全 PASS ／ 有 FAIL（列編號）。發現驗收條件之外的嚴重問題，另列一節。
```

## 常見錯誤（派工前最後檢查）

1. **殘留空白填空**：`〔〕` 沒填完就派 → subagent 亂猜。派前搜一次「〔」。
2. **驗收條件寫成願望**：「程式碼要乾淨」不可判定；改成「diff 只含範圍內變更」可判定。
3. **忘記給落檔路徑**：長產物沒指定路徑，subagent 就會整篇貼回來灌爆主對話。
4. **把實作過程餵給驗收者**：模板 5 的「你是誰」段落存在的意義就是隔離，別好心附上實作總結。
5. **一張單塞多個目標**：一單一目標。兩件事就開兩張單（能平行就平行派）。
